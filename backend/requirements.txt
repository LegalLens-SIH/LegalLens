# `opencv-contrib-python` MUST stay: paddlex (PaddleOCR's backend) does its
# own internal dependency check - independent of pip's dependency graph -
# that hard-requires `opencv-contrib-python==4.10.0.84` by exact name+version
# (see paddlex.utils.deps.EXTRAS["ocr-core"]) before it will construct a
# PaddleOCR pipeline at all. Removing it breaks PaddleOCR with
# "DependencyError: `OCR` requires additional dependencies" even though cv2
# itself still imports fine - confirmed by testing.
#
# `opencv-python-headless` is listed SECOND, deliberately: it must be
# installed after opencv-contrib-python so its files overwrite
# opencv-contrib-python's in the shared `cv2/` site-packages directory - this
# is what makes the *actual* cv2 binary loaded at runtime the headless one
# (verified via `cv2.getBuildInformation()` -> `GUI: NONE`), while
# opencv-contrib-python's pip metadata (which paddlex checks) stays intact.
#
# Plain `opencv-python` (the GUI build) must NEVER appear here: it needs
# system libs (e.g. libGL.so) absent in headless/server/Docker environments.
# ultralytics declares a dependency on it, which is why this file must be
# installed with `--no-deps` (see backend/constraints.txt and
# backend/ocr/README.md) - otherwise a full dependency resolve will
# reintroduce it to satisfy that declared (but here-unneeded) requirement.
